# Контракт программного интерфейса: `typioca completion`

Версия документа: 1.0
Дата: 18.11.2026
Ветка: `lab-3`.

## 1. Операция и её назначение

**Операция:** команда командной строки `typioca completion <shell>`.

**Назначение:** напечатать в стандартный вывод готовый скрипт автодополнения
для bash, zsh, fish или PowerShell, чтобы оболочка подсказывала подкоманды
и флаги `typioca`.

**Связанные требования и сценарии:**

| Требование | Сценарий | Связь |
| --- | --- | --- |
| FR-10 | US-11 | Основной сценарий: пользователь настраивает автодополнение |
| FR-8 | US-8 | Вспомогательный сценарий: администратор находит подкоманду `serve` и её флаги по Tab |

**Реализация:**

- [`src/cmd/cmd.go`](../src/cmd/cmd.go) — корневая команда `RootCmd`, к которой
  Cobra добавляет встроенную команду `completion`;
- [`src/go.mod`](../src/go.mod) — зависимость `github.com/spf13/cobra v1.8.1`,
  которая генерирует скрипты;
- [`src/main.go`](../src/main.go) — вывод ошибки выполнения через `log.Fatal`.

Команда `completion` уже существует в проекте: в лабораторной работе № 3
новый код не добавлялся, описан фактический интерфейс. Проверено 18.11.2026
на Linux amd64, Go 1.25.6, сборка `make build`.

## 2. Контракт

### 2.1. Кто вызывает и как

Команду вызывает человек из оболочки или скрипт установки. Это обычный запуск
процесса, без сети и без интерактивного ввода:

```text
typioca completion [command]
typioca completion bash|zsh|fish|powershell [flags]
```

Вызов не требует TTY, конфигурации typioca или доступа к каталогам кэша.
Команду можно запускать из любого каталога; на поведение влияет только
собранная версия `typioca`.

### 2.2. Входные данные

| Параметр | Тип | Обязательность | Допустимые значения | Поведение |
| --- | --- | --- | --- | --- |
| `<shell>` | подкоманда Cobra | обязательна для получения скрипта | `bash`, `zsh`, `fish`, `powershell`; регистр важен | Выбирает генератор скрипта |
| `-h`, `--help` | флаг | необязателен | — | Печатает справку и завершает работу с кодом `0` |
| `--no-descriptions` | флаг подкоманды оболочки | необязателен, по умолчанию `false` | `true`/`false` | Убирает описания команд из подсказок |

Дополнительных переменных окружения и файлов конфигурации команда не читает.
Флаг `--no-descriptions` указан у каждой подкоманды оболочки; на уровне
`typioca completion` его нет.

### 2.3. Условия вызова

- Бинарный файл `typioca` собран и доступен по имени или по полному пути.
- Для записи результата в файл у вызывающего есть права на целевой каталог;
  сама команда файлов не создаёт.
- Оболочка, для которой генерируется скрипт, не обязана быть установлена на
  машине генерации: она нужна только для использования готового скрипта.

### 2.4. Результат успешного вызова

- Код возврата: `0`.
- Стандартный вывод: текст скрипта автодополнения в кодировке UTF-8,
  заканчивается переводом строки. Скрипт можно передать оболочке напрямую
  или сохранить в файл.
- Стандартный поток ошибок: пуст.
- Побочные эффекты: нет. Команда не пишет файлы, не меняет конфигурацию,
  не сохраняет результаты тестов и не обращается к сети.
- Повторный вызов с теми же аргументами даёт тот же результат.

Содержимое скрипта зависит от дерева команд `RootCmd` и версии Cobra.
После добавления новых подкоманд или флагов скрипт нужно сгенерировать заново.

### 2.5. Поведение при ошибке

Характерная ошибка — лишний аргумент после имени оболочки:

```bash
typioca completion bash extra
```

Поведение:

- код возврата `1`;
- стандартный вывод пуст;
- в стандартный поток ошибок Cobra печатает
  `Error: unknown command "extra" for "typioca completion bash"`, блок `Usage`
  и список флагов;
- затем `log.Fatal` в `src/main.go` повторяет сообщение с отметкой времени,
  например `2026/11/18 21:40:08 unknown command "extra" ...`.

Ошибку можно распознать по коду возврата `1` и подстроке
`unknown command "extra"`.

| Ситуация | Сообщение в stderr | Код |
| --- | --- | --- |
| Лишний аргумент после оболочки | `Error: unknown command "extra" for "typioca completion bash"` + `Usage` | `1` |
| Неизвестный флаг подкоманды | `Error: unknown flag: --badflag` + `Usage` | `1` |
| Флаг `--no-descriptions` без оболочки | `Error: unknown flag: --no-descriptions` + `Usage` | `1` |

### 2.6. Особенности текущей реализации

- `typioca completion` без оболочки печатает справку в **stdout** и завершается
  с кодом `0`.
- Неизвестное имя оболочки, например `typioca completion tcsh`, тоже печатает
  справку и завершается с кодом `0`. Это не ошибка: вызывающая сторона не может
  определить неподдерживаемую оболочку по коду возврата и должна сама сверять
  имя с допустимым списком.
- Имя оболочки чувствительно к регистру: `typioca completion BASH` также
  печатает справку и завершается с кодом `0`.
- Отдельной формы `typioca completion <shell>` с позиционным аргументом нет:
  используются подкоманды `completion bash`, `completion zsh`, `completion fish`
  и `completion powershell`.

## 3. Примеры

### 3.1. Успешный вызов: bash

```bash
typioca completion bash > ~/.local/share/bash-completion/completions/typioca
echo $?
head -n 1 ~/.local/share/bash-completion/completions/typioca
```

Ожидаемый результат:

```text
0
# bash completion V2 for typioca                              -*- shell-script -*-
```

Файл создан, его размер больше нуля, стандартный поток ошибок пуст.
После открытия новой оболочки команда `typioca <Tab>` предлагает
`completion`, `help` и `serve`.

### 3.2. Выбранная ошибка: лишний аргумент

```bash
typioca completion bash extra
echo $?
```

Ожидаемый результат: код `1`, стандартный вывод пуст, в стандартном потоке
ошибок есть строки:

```text
Error: unknown command "extra" for "typioca completion bash"
Usage:
  typioca completion bash
```

и повтор сообщения с отметкой времени от `log.Fatal`.

### 3.3. Дополнительная проверка: без описаний

```bash
typioca completion zsh --no-descriptions > /tmp/_typioca
echo $?
head -n 1 /tmp/_typioca
```

Ожидаемый результат: код `0`, первая строка `#compdef typioca`, скрипт
не содержит описаний команд.

### 3.4. Особый случай: неизвестная оболочка

```bash
typioca completion tcsh
echo $?
```

Ожидаемый результат: код `0`, в stdout напечатана справка команды
`completion`, стандартный поток ошибок пуст, скрипт не создаётся.
