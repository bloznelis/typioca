# Команды командной строки typioca

Версия документа: 1.0
Дата: 18.11.2026
Связанные требования: FR-8, FR-10.

Документ описывает интерфейс, который `typioca` предоставляет в терминале:
запуск TUI, SSH-сервер `serve`, автодополнение `completion` и встроенную справку.
Контракт операции `completion` подробно описан в
[`interface-contract.md`](interface-contract.md).

## 1. Общие правила

`typioca` построен на Cobra. Общий вид вызова:

```text
typioca [command] [flags]
```

- Без подкоманды и без `--version` запускается интерактивный TUI. Для него нужен
  настоящий терминал (TTY).
- `typioca --version` и `-v` печатают версию и не запускают TUI. Версия берётся
  из `git describe` при сборке; в клоне без тегов строка версии может быть пустой.
- `typioca help` печатает общий список команд, `typioca help <command>` —
  справку по команде. Эквивалент: `typioca <command> --help`.
- Успешное выполнение завершается с кодом `0`. При ошибке Cobra печатает
  `Error: <сообщение>` и блок `Usage`, затем `log.Fatal` повторяет сообщение
  с отметкой времени; процесс завершается с кодом `1`.
- Глобальных флагов, кроме `-h/--help` и `-v/--version`, нет.

Доступные команды:

| Команда | Назначение |
| --- | --- |
| `typioca` | Запустить TUI локально |
| `typioca serve` | Запустить встроенный SSH-сервер |
| `typioca completion <shell>` | Напечатать скрипт автодополнения |
| `typioca help [command]` | Показать справку |

## 2. `typioca` — локальный запуск

```text
typioca [flags]
```

Флаги:

| Флаг | По умолчанию | Значение |
| --- | --- | --- |
| `-v`, `--version` | `false` | Напечатать версию и выйти |
| `-h`, `--help` | `false` | Показать справку |

Без флагов приложение открывает главное меню в альтернативном экране терминала.
Если стандартный ввод не является TTY, интерактивный режим работать не будет;
для проверки сборки используйте `typioca --version`.

## 3. `typioca serve` — SSH-сервер

Команда реализует FR-8: администратор инсталляции запускает сервер, а
пользователи подключаются к нему по SSH и проходят тесты удалённо.

```text
typioca serve [flags]
```

`typioca help serve` показывает краткое описание и флаги. Полное поведение
команды, восстановленное по коду:

### 3.1. Флаги

| Флаг | По умолчанию | Значение |
| --- | --- | --- |
| `-b`, `--bind string` | `""` | Адрес, на котором слушает сервер. Пустая строка означает все интерфейсы (`:2229`) |
| `-p`, `--port int` | `2229` | TCP-порт SSH-сервера |
| `-k`, `--key string` | `"typioca"` | Путь к приватному ключу сервера |
| `-h`, `--help` | `false` | Показать справку |

Путь к ключу относительный, если не указан абсолютный. При первом запуске,
если файла по пути `--key` нет, генерируется новый Ed25519-ключ и записывается
в этот файл. При повторном запуске используется существующий ключ.

### 3.2. Что происходит при запуске

1. Создаётся SSH-сервер Wish с адресом `bind:port`.
2. Проверяется ключ: при отсутствии создаётся Ed25519-ключ.
3. Сервер печатает в журнал `Starting server on <bind>:<port>` и начинает
   принимать подключения.
4. Каждое SSH-подключение получает тот же TUI, что и локальный запуск.
   Размер окна берётся из PTY клиента, цвета — из профиля ANSI256.
5. По `Ctrl+C`, `SIGINT` или `SIGTERM` сервер печатает
   `Stopping SSH server on <bind>:<port>` и вызывает `Shutdown` с таймаутом
   30 секунд. В текущей реализации после остановки в журнал дополнительно
   попадает `ssh: Server closed`, а процесс завершается с кодом `1`.

Результаты тестов и конфигурация сохраняются на машине сервера, в каталогах
кэша и конфигурации пользователя, от имени которого запущен `typioca`, а не на
машине клиента.

### 3.3. Требования к клиенту

Клиент обязан выделить PTY. Обычный `ssh -p 2229 <host>` делает это
автоматически в интерактивном режиме. Если PTY нет, сервер закрывает сессию
сообщением:

```text
not a tty
```

### 3.4. Аутентификация и безопасность

`typioca` не добавляет собственную аутентификацию поверх SSH: в сервере
включён режим без проверки клиентского ключа, поэтому любой клиент, который
может подключиться к `bind:port`, получает доступ к TUI. Если сервер доступен
из сети, ограничьте доступ одним из способов:

- слушать только localhost: `--bind 127.0.0.1`;
- закрыть порт межсетевым экраном;
- использовать частную сеть или VPN;
- поставить перед `typioca` отдельный SSH-шлюз с аутентификацией.

Не публикуйте сервер в интернете без такого ограничения.

### 3.5. Примеры

Сервер на всех интерфейсах, порт 2229, ключ по умолчанию:

```bash
typioca serve
```

Сервер на порту 2229, доступный из сети, с явным путём к ключу:

```bash
typioca serve --bind 0.0.0.0 --port 2229 --key /var/lib/typioca/host_key
```

Только локальные подключения:

```bash
typioca serve -b 127.0.0.1 -p 2229 -k ~/.ssh/typioca_host_key
```

Подключение клиента:

```bash
ssh -p 2229 user@host
```

### 3.6. Типичные ошибки

| Симптом | Причина | Что делать |
| --- | --- | --- |
| `listen tcp ... bind: address already in use` | Порт занят | Указать другой `--port` или остановить процесс |
| `permission denied` при создании ключа | Нет прав на каталог | Указать доступный `--key` или изменить права |
| Клиент сразу отключается с `not a tty` | Нет PTY | Запускать `ssh` в интерактивном терминале или с `-t` |
| Подключение висит или отклоняется | Порт закрыт или неверный адрес | Проверить `--bind`, `--port` и межсетевой экран |

## 4. `typioca completion` — автодополнение

```text
typioca completion [command]
typioca completion bash|zsh|fish|powershell [--no-descriptions]
```

Команда встроена в Cobra и печатает в стандартный вывод скрипт автодополнения
для выбранной оболочки. Она ничего не записывает на диск: чтобы сохранить
скрипт, перенаправьте вывод. Оболочки: bash, zsh, fish и PowerShell.

Флаг `--no-descriptions` есть у каждой подкоманды оболочки и отключает описания
команд в подсказках.

Примеры:

```bash
# bash
typioca completion bash > ~/.local/share/bash-completion/completions/typioca

# zsh
source <(typioca completion zsh)

# fish
typioca completion fish | source

# PowerShell
typioca completion powershell | Out-String | Invoke-Expression
```

Особенности текущей реализации:

- `typioca completion` без оболочки печатает справку в stdout и завершается
  с кодом `0`.
- Неизвестное имя оболочки, например `typioca completion tcsh`, тоже печатает
  справку и завершается с кодом `0`: это не ошибка.
- Лишний аргумент после имени оболочки, например
  `typioca completion bash extra`, является ошибкой: код `1`, пустой stdout,
  в stderr — `Error: unknown command "extra" for "typioca completion bash"`,
  блок `Usage` и повтор сообщения от `log.Fatal` с отметкой времени.
- Неизвестный флаг, например `typioca completion bash --badflag`, даёт такую же
  ошибку с кодом `1`.

Полный контракт, включая точные сообщения и примеры, — в
[`interface-contract.md`](interface-contract.md).

## 5. Справка

```bash
typioca help
typioca help serve
typioca serve --help
typioca completion --help
```

`typioca help serve` показывает краткое назначение команды и флаги. Требования
к PTY, поведение ключа и ограничения безопасности описаны в разделе 3 этого
документа.
